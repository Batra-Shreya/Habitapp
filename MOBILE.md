# 📱 Getting Habitat on the Play Store (and earning from it)

This is the honest, end-to-end plan — how apps like this are actually built and
shipped, what it costs, how long it takes, and how the money works.

---

## First: how a phone app is really built

There are three common ways to make an Android app. We're using the fastest one
that fits what we already have.

| Approach | What it is | Effort | We use it? |
|----------|-----------|--------|------------|
| **Native** (Kotlin/Java) | Written from scratch for Android | Highest — full rewrite | ❌ |
| **Cross-platform** (Flutter, React Native) | One codebase → Android + iOS, still a rewrite | High | ❌ (later, maybe) |
| **Web-app wrapper** (PWA + Capacitor) | Wrap our existing web app in a native shell | Low — reuse everything | ✅ **yes** |

Habitat is already a web app. Wrapping it means we ship the *same* app you're
using now, but as a real installable Android app — and we can add native powers
like **push-notification reminders** ("Time to drink water 💧"), which are perfect
for a habit tracker and a great reason for people to keep the app.

## The plan, step by step

### ✅ Step 0 — Make it installable (DONE, on this branch)
An installable app needs a **PWA foundation**. I've added it:
- `public/manifest.webmanifest` — app name, colors, icons
- `public/icons/*` — real app icons (generated by `npm run icons`)
- `public/service-worker.js` — lets the app load offline and be "installed"

Right now, on your deployed Render URL, Chrome on Android will already offer
**"Add to Home screen"** — that's a real installed app, no store needed. Try it:
open your Render link in Chrome → menu (⋮) → *Add to Home screen*.

### Step 1 — Make it product-ready (before the store)
The store isn't the hard part; a trustworthy app is. Needed first:
1. **Persistent database** — replace the temporary file so nobody loses data.
   (I can do this — Render Disk, or a hosted Postgres.)
2. **Basic security hardening** — rate-limit logins, longer passcodes, buddy
   requests. (Small, I can do it.)
3. **A privacy policy** — Google *requires* a public privacy-policy URL. It's a
   simple page; I can draft it.
4. **A paid, always-on host** — the free Render tier sleeps and wipes data. A real
   app needs ~**$7/month** hosting.

### Step 2 — Wrap it as an Android app (Capacitor)
On a computer (this part needs a desktop with Android Studio — not doable from a
phone):
```bash
npm install @capacitor/core @capacitor/cli @capacitor/android
npx cap init Habitat com.yourname.habitat --web-dir=public
npx cap add android
npx cap open android        # opens Android Studio to build/run
```
Capacitor turns `public/` into a native app and auto-generates all icon sizes
from our 512px icon. Add `@capacitor/push-notifications` for reminders. Output is
an **`.aab`** file (Android App Bundle) — that's what the store wants.

### Step 3 — Google Play Console setup
1. **Create a Play Developer account** — one-time **$25 fee**, at
   [play.google.com/console](https://play.google.com/console). Personal or a
   company; personal is fine to start.
2. **Create the app** and fill the listing:
   - Title, short + full description
   - **Screenshots** (phone), an app icon (512px — we have it), a feature graphic
   - Category (Health & Fitness / Lifestyle)
   - **Privacy policy URL** (from Step 1)
   - **Data safety** form — declare what you collect (username, habits). Be honest.
   - **Content rating** questionnaire
3. **Upload the signed `.aab`.**

### Step 4 — The testing requirement (important, often surprising)
Since 2023, **new personal developer accounts must run a closed test with at least
12 testers for 14 continuous days** before Google lets you publish to the public.
So the realistic timeline is: build → invite ~12 friends to test → wait 2 weeks →
apply for production → Google review (a few days) → **live**.

### Step 5 — Publish 🎉
Submit for review. Once approved, it's on the Play Store. Updates later are just a
new `.aab` upload.

## 💰 How the earning works (honest version)

You don't get paid for being on the store — you get paid when people **use** the
app. The realistic models, best-first for something like this:

1. **Freemium + subscription** (recommended). App is free; a **Premium** tier
   ($1–3/month) unlocks things like unlimited habits, extra buddies, richer stats,
   themes, and reminders. Uses **Google Play Billing**. Google takes **15%** of
   subscription revenue (under $1M/yr), you keep 85%.
2. **One-time in-app purchase** — pay once to unlock Premium. Simpler, but less
   recurring income.
3. **Ads** (Google AdMob) — show ads to free users. Easiest to add, but pays
   little unless you have *lots* of users (roughly $1–$5 per 1,000 ad views).
4. **Paid app** (pay to download) — hardest; most people won't pay before trying.

**The honest truth about the money:** the store fee ($25) and the build are the
easy, cheap part. **Revenue depends almost entirely on getting users**, and that
depends on marketing, not code. Most indie apps earn little; the ones that succeed
solve a real need and get shared. A buddy/accountability angle (which we have) is
genuinely a good hook because users invite each other — that's built-in growth.

**Rough starting budget:** $25 (store, once) + ~$7/mo (hosting) + your time. You
can validate demand *before* spending much by sharing the installable PWA link.
